# مدرسه‌یار — اپلیکیشن معلم اندروید A02 برای GitHub

**وضعیت: سورس آزمایشی قابل بارگذاری در GitHub؛ APK اینجا ساخته یا روی گوشی تست نشده است.**

## ساخت APK در GitHub بدون کامپیوتر

۱. در GitHub یک مخزن جدید (ترجیحاً Private) با نام `madreseyar-teacher-android` ایجاد کن.

۲. تمام **محتوای این پوشه پروژه** را در ریشه مخزن قرار بده؛ به‌خصوص فایل `.github/workflows/build-debug-apk.yml` (پوشه مخفی `.github` را جا نگذار).

۳. در مخزن GitHub به بخش **Actions** برو؛ گردش‌کار **Build teacher Android APK (test)** را انتخاب کن و **Run workflow** را بزن. با هر Push روی `main` یا `master` هم خودکار ساخته می‌شود.

۴. پس از سبز شدن اجرای گردش‌کار، در پایین همان صفحه **Artifacts** را باز کن و بسته `Madreseyar-Teacher-A02-FIX02-Debug-APK` را بگیر. ZIP خروجی حاوی `app-debug.apk` است؛ آن را استخراج و روی گوشی آزمایشی نصب کن.

۵. خروجی فعلاً **Debug APK** است، مناسب تست و نه انتشار رسمی در گوگل پلی. امضای دیباگ در هر اجرای GitHub ممکن است عوض شود؛ برای نصب نسخه جدید شاید لازم باشد قبلی را حذف کنی.

## نحوه ورود با اثر انگشت

۱. در اجرای نخست با کد ملی/نام کاربری و رمز عبور حساب **معلم** در صفحه رسمی `/app/` وارد شو.

۲. بعد از بازشدن پنل معلم، برنامه یک بار پیشنهاد فعال‌سازی اثر انگشت می‌دهد. با تأیید آن، حسگر امن گوشی را تأیید کن. اگر پیشنهاد را رد کردی، هر زمان خواستی روی علامت 👆 در نوار بالای خود اپ بزن.

۳. از دفعات بعد، هنگام بازکردن برنامه ابتدا قفل امن بیومتریک نشان داده می‌شود. بعد از تأیید، اعتبار نشست با سرور چک می‌شود و پنل اصلی معلم برمی‌گردد.

۴. رمز ورود مدرسه ذخیره نمی‌شود. فقط توکن نشست با کلید سخت‌افزاری/امن Android Keystore رمزگذاری و در حافظه خصوصی برنامه نگهداری می‌شود. وقتی نشست منقضی شده، حساب غیرفعال شده، انگشت‌های ثبت‌شده تغییر کرده یا رمز اولیه هنوز باید عوض شود، ورود دوباره با رمز لازم است.

۵. در صفحه قفل گزینه **«ورود با نام کاربری و رمز»** برای کنارگذاشتن نشست بیومتریک وجود دارد. برای غیرفعال‌سازی اختیاری، در حالت واردشده دوباره روی 👆 بزن.

**توجه:** رابط استاندارد اندروید «بیومتریک قوی» است؛ روی بعضی گوشی‌ها تشخیص چهره امن هم می‌تواند استفاده شود. بدون حسگر قوی تنظیم‌شده، ورود عادی با رمز کار می‌کند. بدون اینترنت، نشست بیومتریک عمداً باز نمی‌شود، زیرا سرور مدرسه باید اجازه دسترسی را تأیید کند.

## محدودیت‌های تست

- این برنامه پوسته موبایل وب‌اپ اصلی `https://scooljavanrood.ir/app/` است؛ هنوز برابری واقعی تمام امکانات با پنل وب نیازمند آزمون گوشی و تأیید معلم است.
- کارکرد آزمون‌ساز، تصحیح، مرکز تکالیف، ثبت نمرات، حضورغیاب، دانلود Blob، فایل و دوربین، پنجره PDF و چاپ جداگانه بررسی شود.
- احراز هویت حساب معلم برای فعال‌سازی اثر انگشت از مسیر `GET /app/api/staff/me` انجام می‌شود؛ بازیابی از مسیر موجود `?p635_return=1` استفاده می‌کند.
- چون ورود اولیه در پنل **مشترک** معلم و مدیر است، ممنوعیت قطعی ورود مدیر در کل وب‌اپ نیازمند کنترل سیاست سمت سرور است؛ در این نسخه فقط بازیابی بیومتریک نقش معلم را می‌پذیرد.
- برنامه با `FLAG_SECURE` از گرفتن اسکرین‌شات صفحه‌های حساس جلوگیری می‌کند. برای فرستادن گزارش تست، خطاها را بدون داده محرمانه یادداشت کن.
- داده واقعی مدرسه، دیتابیس و رمز ورود داخل مخزن نیست. سورس مادر و فایل‌های هاست دست‌نخورده مانده‌اند.

**بازگشت:** چون چیزی روی هاست نصب نشده، حذف اپ اندروید آزمایشی برای بازگشت کافی است. اگر فقط می‌خواهی اثر انگشت غیرفعال شود، از دکمه 👆 داخل خود اپ استفاده کن.


## اصلاح GitHub SDK — A02-FIX01 (۱۶ اکتبر ۲۰۲۶)

اگر در Actions مرحله `Install Android SDK` با خطای `Failed to find package 'tools'` متوقف شد، علت استفاده از نسخه قدیمی `android-actions/setup-android@v3` بود. این نسخه به `@v4` تغییر کرده و فقط بسته `platform-tools` نصب می‌شود؛ سپس Android Platform 35 و Build Tools 35 در مرحله بعد نصب می‌شوند.

**برای مخزنی که A02 را قبلاً آپلود کرده‌ای:** کافی است فایل `.github/workflows/build-debug-apk.yml` را با نسخه FIX01 جایگزین کنی و در تب Actions گزینه Run workflow را دوباره بزنی. کد اپ، قابلیت اثر انگشت، مسیر سرور، هاست و دیتابیس تغییر نکرده‌اند.

تا زمان سبز شدن اجرای Github Actions، موفقیت تولید APK تأیید نیست. اگر خطای جدیدی در بخش Compile پیش آمد، گزارش نخستین خطا را بفرست.


## اصلاح کامپایل A02-FIX02 — ۱۷ اکتبر ۲۰۲۶

در مرحله Compile test Android APK خطای Gradle رخ داده بود؛ اسکرین‌شات فقط انتهای stack trace را نشان می‌داد و پیام اصلی را نمایش نمی‌داد. در بازبینی ایستای سورس، ارجاع به `Activity.RESULT_OK` بدون `import android.app.Activity;` یافت و اصلاح شد.

برای مخزن GitHub موجود، فقط دو فایل زیر را جایگزین کن:

- `app/src/main/java/ir/scooljavanrood/madreseyar/teacher/MainActivity.java`
- `.github/workflows/build-debug-apk.yml`

Workflow حالا متن لاگ کامپایل را هم در فایل `gradle-build.log` نگه می‌دارد و هنگام شکست، قطعه‌های خطای اصلی را در مرحله `Show primary build errors` نشان می‌دهد. یک Artifact با نام `Madreseyar-Teacher-A02-FIX02-Build-Log` هم در صورت شکست ساخته می‌شود.

**دقت:** این پچ براساس ایراد تأییدشده در بازبینی کد ساخته شده است؛ از روی تصویر نمی‌توان قطعی گفت تنها علت خطای GitHub همین بوده است. تا زمان اجرای مجدد Actions، موفقیت ساخت APK تأیید نشده است. مسیر سرور، توکن، اثر انگشت و دیتابیس دست‌نخورده مانده‌اند.


## رفع کلاس‌های تکراری Kotlin — A02-FIX03 (۱۷ اکتبر ۲۰۲۶)

GitHub Actions از مرحله SDK و خطای Java قبلی عبور کرده و در مرحله `Compile test Android APK` با خطای `Duplicate class kotlin...` روبه‌رو شده است. در گزارش عکس، `kotlin-stdlib:1.8.22` با `kotlin-stdlib-jdk7/jdk8:1.6.21` تداخل دارند.

در `app/build.gradle` وابستگی BOM رسمی `org.jetbrains.kotlin:kotlin-bom:1.8.22` اضافه شده تا نسخه‌های Kotlin استاندارد و افزونه‌های jdk7/jdk8 هم‌راستا شوند. این راهکار مطابق مستندات Kotlin است و با غیرفعال‌کردن تشخیص کلاس تکراری فرق دارد.

**برای مخزن موجود فقط یک فایل جایگزین شود:** `app/build.gradle` از ZIP کوچک `A02_FIX03_ONE_FILE_PATCH`. بعد از Commit، در GitHub Actions دوباره `Run workflow` اجرا شود. نسخه FIX03 روی GitHub ساخته نشده و بیلد موفق تضمین‌شده نیست. اگر هنوز ناموفق شد، خروجی `Show primary build errors` و Artifact لاگ را بفرست.

**بدون تغییر:** جاوا/بیومتریک، سرور، دیتابیس، فایل‌های هاست، رابط پنل معلم و سورس مادر.
