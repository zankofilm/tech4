# Madreseyar — Teacher Android A02 (GitHub build)

**Status:** Test source, not a released APK. Uses the existing teacher portal at `https://scooljavanrood.ir/app/`, without changes to the school server or database. The full teacher-feature parity checklist still needs on-device testing.

## Build an APK using GitHub (no local Android Studio required)

1. Create a **private** GitHub repository (recommended) named `madreseyar-teacher-android`.
2. Upload the **contents of this project folder** to the repository root, including the hidden `.github/workflows/build-debug-apk.yml` file.
3. Open **Actions** → **Build teacher Android APK (test)** → **Run workflow**.
4. After a successful build, open that workflow run and download the `Madreseyar-Teacher-A02-Debug-APK` artifact.
5. Extract `app-debug.apk` from the artifact ZIP. Install it on an Android test phone (Android 8.0+). This is a **debug** APK, not a signed production release.

Actions also builds automatically when commits are pushed to `main`/`master`. The workflow pins JDK 17, Gradle 8.9, Android SDK 35 and Android Gradle Plugin 8.7.3. The workflow intentionally does not use a Gradle wrapper.

## Fingerprint / strong biometric entry

1. Open the app and sign in once using your **teacher** username and password in the existing school portal.
2. After the teacher dashboard is visible, the app offers biometric setup **once**. Accept the prompt (or tap the **👆** icon later if you dismissed it).
3. Confirm the phone's strong biometric prompt. The app stores **only the existing staff-session token**, encrypted with a non-exportable Android Keystore key requiring a fresh biometric authentication each time. **It never stores the password**.
4. On later launches, approve the biometric prompt to reopen the teacher session. The app also checks `GET /app/api/staff/me` over HTTPS; role must be `teacher`, session must be valid, and initial-password change must already be completed.
5. If the server session expires, the account is disabled, the phone's enrolled fingerprints change, or the user chooses **ورود با نام کاربری و رمز**, a fresh username/password login is required.
6. To turn biometrics off, tap the same 👆 icon after unlocking and confirm. Switching between teacher accounts requires re-enabling biometrics for the desired account.

**Important:** Android's biometric prompt can allow any *strong biometric* enrolled on the phone (fingerprint or strong face recognition where supported). Apps cannot reliably force fingerprint-only on every Android device. Without an enrolled strong biometric, standard username/password login remains available. Offline biometric login is intentionally not supported because the school server must validate the session.

The app uses `/app/?p635_return=1`, the existing teacher-return mechanism in the supplied web source, to resume a verified session. No new API endpoints are introduced. Other hosted versions must preserve this route and the current session-storage keys to keep biometric resume working.

## Test scope and limitations

- WebView uses the full existing `/app/` teacher portal; *Android wrapper source ≠ guaranteed feature parity*. Test each of the 30 teacher workflows in the supplied matrix.
- Browser download, print/PDF, HTML `blob:` downloads, file picking, popup windows, offline work, and attachment submissions must be tested on physical devices and fixed where needed.
- Teacher-only native biometric restore is checked by the server. The shared web sign-in page can still admit other staff roles; enforcing a dedicated teacher-only login for the whole WebView requires a separate product/server policy review.
- Sensitive screens are protected from Android screenshots/recents by `FLAG_SECURE`.
- Debug APK generated by GitHub Actions uses an ephemeral debug signing key. To upgrade an installed test app from a different workflow run, Android may require uninstalling the previous debug APK (app-local data is then lost). Do **not** use it for production or upload keystore/password files to GitHub.
- This project contains no real student data, teacher credentials, live database, or server source.

## GitHub SDK hotfix A02-FIX01
The former `android-actions/setup-android@v3` default included obsolete SDK package `tools`, causing `Failed to find package 'tools'`. The workflow now uses `android-actions/setup-android@v4` with `packages: 'platform-tools'`. It still installs `platforms;android-35` and `build-tools;35.0.0` separately. No Java source, host, or school data changed. GitHub build and device QA still pending.


### A02-FIX02 (Android compile and CI diagnostics)
`MainActivity.java` now imports `android.app.Activity` as needed by `Activity.RESULT_OK`. GitHub Actions captures compiler errors to `gradle-build.log` and uploads the log on failure. This fix is statically audited but not yet built on GitHub.
